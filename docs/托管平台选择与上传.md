# 托管平台选择与上传指南

本仓库已经完成协作化改造，**可以直接推送到任意 Git 托管平台**。
这份文档帮你选平台、并把代码推上去。

---

## 一、先看本项目的体积特点

选平台前必须先看这三个数字，它们直接决定哪个平台能用：

| 指标 | 本项目的值 |
|---|---|
| 仓库总体积 | **135 MB** |
| 最大单文件 | **43.6 MB**（`金榜题名v0.17.4/动态/video_menu.m4v`） |
| 第二大文件 | 11.7 MB（`音乐/bgm_wukelili.wav`） |
| LFS 追踪体积 | 约 57 MB（上述两个 + `龙族动态.mp4`） |

> 43.6 MB 这个数字很关键 —— 它会撞上某些平台的单文件红线。

## 二、三个平台对比

| | **GitHub** | **Gitee（码云）** | **GitCode** |
|---|---|---|---|
| 国内访问速度 | 慢，偶尔需代理 | 快 | 快 |
| 单仓库容量 | 1 GB（软限制） | **500 MB（硬限制）** | 10 GB |
| 单文件上限 | 100 MB | **50 MB（硬限制）** | 100 MB |
| Git LFS | **10 GB 存储 + 10 GB/月带宽** | 免费版政策不明确，可能不支持 | 免费额度较宽松 |
| 私有仓库 | 免费 | 免费 | 免费 |
| 协作功能 | PR / Issue / Actions 最完善 | PR / Issue / Gitee Go | PR / Issue |
| 本项目可行性 | ✅ 很充裕 | ⚠️ 能放，但很贴红线 | ✅ 充裕 |

### 关键结论

- **Gitee 的风险点**：单文件硬限制 50 MB，而你的视频是 43.6 MB —— **只剩 6 MB 余量**。
  以后只要新增一个稍大的素材（比如另一段演出视频），就会直接推送失败，且必须重写历史才能移除。
  另外 Gitee 免费版对 Git LFS 的支持存在限制，企业版帮助文档明确写着 LFS 需付费企业版。
- **GitHub 的短板**：国内 clone/push 速度慢，队友可能需要在网络环境上花点功夫。
- **GitCode**：国内访问 + 宽松限额，是 Gitee 的替代选项，但生态相对较新。

## 三、推荐方案

### 首选：GitHub

理由：LFS 给到 10 GB 存储 + 10 GB/月带宽，是本项目最需要的；单文件 100 MB、仓库 1 GB 的额度对 135 MB 的仓库非常宽裕；协作功能最完整。

**顺带一个福利**：你是浙江传媒学院在读学生，可以申请 **GitHub Student Developer Pack**（<https://education.github.com/pack>），用学校邮箱或学信网在读证明即可。通过后免费获得 GitHub Pro、Copilot，以及一批开发工具。申请前记得把学校邮箱加到 GitHub 账号里。

### 备选：Gitee

如果队友的网络条件确实不适合 GitHub，选 Gitee 也能跑，但**必须做两件事**：

1. 去掉 `.gitattributes` 里的 Git LFS 规则（Gitee 免费版可能不支持，会导致推送报错）
2. 接受 50 MB 单文件红线，以后新增素材前先压缩

## 四、上传步骤

### 步骤 1：在平台上创建空仓库

- 打开 GitHub / Gitee，右上角 `+` → **New repository**
- 仓库名建议：`student-era-cards`
- **不要**勾选 "Add a README file" / "添加 .gitignore" / "选择许可证"
  （本仓库已有这些文件，勾了会产生冲突）
- 选择 **Private（私有）** 或 Public 按需决定

### 步骤 2：本地关联远程仓库并推送

在仓库根目录（`D:/学生时代牌网页群主版本`）执行：

```bash
# 换成你刚创建的仓库地址
git remote add origin https://github.com/<你的用户名>/student-era-cards.git

# 首次推送
git push -u origin main
```

推送时 Git Credential Manager 会弹出登录窗口，登录一次即可，之后会记住。

> 仓库较大（135 MB，含 LFS 对象），首次推送需要几分钟，属正常现象。

### 步骤 3：确认 LFS 文件已正确上传

```bash
git lfs ls-files      # 应列出 3 个媒体文件
```

到平台网页上点开 `金榜题名v0.17.4/动态/video_menu.m4v`，文件大小应显示 43.6 MB 左右，而不是几百字节的指针文本。

### 步骤 4：邀请队友

- **GitHub**：仓库 → Settings → Collaborators → Add people
- **Gitee**：仓库 → 管理 → 仓库成员管理 → 添加成员

队友克隆后**务必提醒**执行一次：

```bash
git lfs install
git lfs pull
```

否则视频和音频拿到的是指针文件，游戏里会没有声音。

## 五、常见问题

**Q：推送报错 `exceeds the file size limit`**
说明撞上了单文件红线。Gitee 是 50 MB，GitHub 是 100 MB。
解决：压缩该文件（视频用 ffmpeg 降码率，音频改用 OGG 格式），重新提交。

**Q：推送很慢或中断**
135 MB 首次推送本身就不快。若在 GitHub 上反复失败，检查是否走了代理；Git 的代理需要单独配置：

```bash
git config --global http.proxy http://127.0.0.1:端口
git config --global https.proxy http://127.0.0.1:端口
# 取消：
# git config --global --unset http.proxy
```

**Q：队友克隆后没有声音 / 视频不播放**
LFS 文件没拉下来。执行 `git lfs install && git lfs pull`。

**Q：想改用 Gitee，但已经推了 GitHub**
直接加一个 Gitee 远程即可，两边可以同时存在：

```bash
git remote add gitee https://gitee.com/<用户名>/student-era-cards.git
git push -u gitee main
```

> 193 个文件全部是游戏代码与美术素材。

### 本地代理配置

国内直连 GitHub 不稳定，因此本仓库**单独**配置了 HTTP 代理（只影响这个仓库，不动全局 git 配置）：

```bash
git config --local http.proxy http://127.0.0.1:7897
git config --local https.proxy http://127.0.0.1:7897
```

**仅在 Clash 运行时有效。** 如果以后换了网络环境、不需要代理了，清掉即可：

```bash
git config --local --unset http.proxy
git config --local --unset https.proxy
```

### 排查记录（同类问题可参考）

首次推送时 GitHub **完全不可达**（DNS 正常但 TCP 超时）。排查路径：

1. 基础网络正常（百度 200、Gitee 200），仅 GitHub 不通 → 排除断网
2. 逐个测试本地代理端口（7897 / 9090 等）→ 全部转发失败
3. 查看 Clash 内核日志发现关键行：
   `dial tcp 54.250.247.167:7001: i/o timeout`
4. 通过内核控制通道（Windows 命名管道）读到策略组状态：
   **GLOBAL 模式选中的是失效节点 `2x专线-日本-3`**，而「自动选择」组早已选到可用的 `美国洛杉矶-4`
5. 切换 GLOBAL 到可用节点 → GitHub 立即恢复

> **经验**：Clash 处于 GLOBAL 模式时，一切流量都走 GLOBAL 组的选中节点，会覆盖「自动选择」的智能结果。
> 再次遇到推送超时，先去 Clash Verge 确认节点是否可用，别急着怀疑 git 配置。
