# 新成员接入指南

这份文档是给**刚被拉进来一起做游戏的人**看的。跟着走一遍，大约 10 分钟就能开始改东西。

---

## 一、先搞清楚你要以什么身份参与

仓库现在有两种参与方式，**先看你在哪一类**：

| | **核心成员**（协作者） | **外部贡献者**（任何人） |
|---|---|---|
| 怎么进 | 由仓库主在后台添加你 | 不需要任何人批准 |
| 权限 | 可以直接往仓库推代码 | 只能改自己的副本，再提 PR |
| 流程 | 开分支 → 改 → 推 → 开 PR | **Fork** → 改 → 推自己的副本 → 提 PR |
| 适合 | 长期一起做的固定班底 | 偶尔贡献、想试试水的群友 |

两类人的**改动最终都要经过 Pull Request（PR）审核**才能进 `main`，这一点是一样的。

---

## 二、准备工作（两类人都要）

### 1. GitHub 账号
没有的话去 <https://github.com> 注册一个。国内访问可能需要代理。

### 2. 安装 Git
- Windows：<https://git-scm.com/download/win>（一路下一步即可）
- macOS：终端执行 `git --version`，没有的话会提示你装

### 3. 安装 Git LFS（**必须，否则游戏没声音**）
- Windows：<https://git-lfs.com> 下载安装
- macOS：`brew install git-lfs`

> 为什么必须装：项目里的视频、音频用了 Git LFS 托管。
> 不装的话，你拿到的是几百字节的"指针文件"，游戏跑起来会静音、视频不播放。

### 4. Node.js（可选）
只有需要跑资源校验脚本才装：<https://nodejs.org>

---

## 三、拿到代码

### 如果你是被加为协作者的

先在 GitHub 上接受邀请（会收到邮件，或去 <https://github.com/notifications> 看），然后：

```bash
git clone https://github.com/lovhastum-png/student-era-cards.git
cd student-era-cards
git lfs install && git lfs pull
```

### 如果你是外部贡献者

先在仓库页面右上角点 **Fork**，把仓库复制到你自己的账号下，然后克隆**你自己的那份**：

```bash
git clone https://github.com/<你的用户名>/student-era-cards.git
cd student-era-cards
git lfs install && git lfs pull
```

## 四、先跑起来看一眼

在项目根目录下，二选一：

**Windows**：双击 `金榜题名v0.17.4/启动游戏.vbs`

**跨平台**（推荐，需要 Python）：
```bash
python -m http.server 8080 --directory 金榜题名v0.17.4
```
然后浏览器打开 <http://localhost:8080/学生时代牌-网页版.html>

能进主菜单、能开一局，就说明环境没问题了。

## 五、开始改东西

### 1. 开一个分支（别直接在 main 上改）

```bash
git switch -c content/你改的内容
```

分支名前缀按类型选：`content/`（内容）、`fix/`（修 bug）、`feat/`（新功能）、`art/`（素材）。

### 2. 改完先自检

```bash
node tools/check-assets.mjs
```

这个脚本会检查你有没有引用不存在的素材、JS 有没有语法错误。
**它会真的抓出问题** —— 项目历史上有过"事件框引用了不存在的图片、背景一直全黑"这种坑。

游戏本身也要跑一遍，确认能进主菜单、能开一局。

### 3. 提交并推送

```bash
git add -A
git commit -m "content: 新增运动会系列事件"
git push -u origin content/你改的内容
```

提交信息的格式是 `类型: 说明`，详见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

> 协作者推到 `origin`；外部贡献者推到自己的 fork，命令里把 `origin` 换成你的 fork 名即可。

### 4. 开 Pull Request

推送后 GitHub 会在仓库首页显示一个黄色的 **Compare & pull request** 按钮，点它，写清楚你改了什么、怎么验证的，然后提交。

等审核通过合并，你的改动就正式进游戏了。

## 六、新手最容易踩的四个坑

**① 游戏没声音 / 视频不播放**
Git LFS 没拉下来。执行 `git lfs install && git lfs pull`。

**② 推送时报 `file size limit` 或超时**
国内访问 GitHub 不稳定。如果开了代理，给 git 单独配上（只影响这个仓库）：
```bash
git config --local http.proxy http://127.0.0.1:7890   # 端口换成你自己代理的
```

**③ 直接改了 `js/data.js` 里的数值，结果冲突了**
改已有数值**优先写进 `js/editor-overrides.js`**（覆盖层），别动基底数据文件——冲突面小、好回滚。详见 README 的「两层覆盖机制」。

**④ 用游戏编辑器改的东西，别人看不到**
编辑器改动只存在你自己浏览器的 `localStorage` 里。要贡献出去，得点编辑器里的「写入游戏」生成 `editor-overrides.js`，再提交这个文件。
